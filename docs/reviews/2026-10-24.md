# MoonBit upstream review — 2026-10-24

This records implementation-stage validation, before the separately authorized
release. Publication outcomes are recorded in the [release follow-up](2026-10-24-release.md).

## Scope and result

17 active original repositories were assessed. The implementation adopts the
new script front matter and permissions, ports the runner's upstream changes,
repairs the codecs canary setup, and refreshes consumer dependencies as part of
release preparation. Archived repositories, upstream forks and experimental
worktrees are excluded. No push, PR, tag, package publication or deployment was
performed. Existing uncommitted RISC-V debugger work is untouched.

The runner's Bun async comparison remains **UNSTABLE**: the `Process::wait`
timing assertion fails twice. This is not added to the expected-difference list.
The other observed runtime differences have exact, reviewed fingerprints.

## Adoption decisions

| Upstream change | Decision and concrete effect |
|---|---|
| `.mbtx` `----` front matter | Migrated 36 existing scripts. All 38 tracked/new script entrypoints type-check on the pinned compiler, including scripts that must not be executed during validation. |
| Script `permission(...)` | The shared docs audit now declares only repository-relative filesystem reads. Its seven copies remain identical; each audit and self-test passes. |
| Runner permission grammar | Reuse upstream `moon_pkg` lexer/parser/syntax with front matter, rather than maintaining another parser. Add minimal import/backend shims; compile and regenerate the policy component. Valid and invalid permission blocks are compared with the real runner. |
| Diagnostic source/runtime locations | Port the upstream renderer and retain named-frame runtime locations. Recover Deno's function indices from code offsets for named frames too; regression tests cover both named and anonymous frames. |
| Console classification and async ABI | Add console kind 8 for the new stdio/generic-stat API; preserve legacy descriptor kind 7. Expose console jobs with upstream Linux `ENOSYS`, UTF-16 bounds and existing resource ownership. |
| Async/SQLite import registrations | Regenerate 266 async and 40 SQLite imports. Update the SQLite parser for `Caller`'s second lifetime and reject a zero/incomplete parse, preventing silent loss of the ABI inventory. |
| TLS paths and poll resource ownership | Inspected existing cwd-bound file ports and JS resource references. Existing mechanisms and regression suites cover these paths; no speculative OS-specific rewrite was added. |
| Conditional package imports (`#cfg`) | **Deferred.** The shipped moon parser accepts them, but the matching moonc rejects the original `moon.pkg` (4192/3002). Tried in SDK packages, then reverted. Retain warning suppression with the actual reason recorded. |
| Core async/checksum consolidation | **Deferred.** These upstream-main changes are absent from the core shipped with this compiler. Reconsider after a matching release is available. |
| Rabbita URL fix | Adopt 0.16.7. Keep the graph site's `new URL(..., baseURI)` wrapper: fixing root-relative URLs does not replace the wrapper's handling of other relative forms. |

The runner's reused policy wasm grows to 1262.8 KiB (489.8 KiB gzip), principally
because it now includes the upstream package grammar. This cost buys one shared
permission parser rather than a divergent implementation. All four generated
components rebuild byte-identically with the committed artifacts and pass the
import-surface checks.

| Bun 1.4.2 | Same test counts and successful outcomes; 93/132 byte-identical, remaining 39 match reviewed D3 fingerprints on each target | **UNSTABLE**. D16/D33 match, but `spawn_in_group_test.mbt` index 2 differs twice. No new flaky exception was added. |

Six live skills conformance cases also match the reference runner exactly.
The Bun D3 refresh reviews 678 result records across both core targets: only
unavailable JSC frame details and the already-known engine trap wordings differ.
The exact output fingerprints remain enforced; stdout is not broadly normalized.

The remaining Bun test measures 500 ms from *after* spawn returns and floors the
duration into 250 ms ticks. A dedicated probe observed spawn=26 ms,
wait=494 ms, total=520 ms, exit=42; another wait was 499 ms with total=505 ms.
The reference's waits were 503–505 ms. This supports a timing-boundary explanation,
not a proven wait/lifecycle defect. Artificially delaying completion would change
the API to satisfy the assertion, so no such change was made. Bun's full async
compatibility remains a release caveat until this assertion is resolved.

The harness also fixes two causes of misleading comparisons: reference caches
now include compiler/runner/source identities, and the nested async checkout has
its own CommonJS package scope. Concurrent helper-build summaries are compared
as exact multisets under `--unordered`; other arbitrary output retains its order.
Runtime async suites were rerun sequentially after shared fixture collisions.

Authored files pass whitespace checks. The verbatim upstream `moon_pkg/parser.rs`
has a trailing space inside a raw-string parser test input; it is retained to
preserve that upstream test, and `sync-upstream --check` confirms the extraction.

### Codec proof, coverage and performance follow-up

The exact Docker image passed the full normal gates, including all four
backend suites, generated vector checks (including APNG), Z3's 22 packages and
negative controls (332.6 s), fmt and info. All four coverage ledgers passed.
Brotli's 3071 streams and the DEFLATE/zlib/gzip encoders' 1092 streams decode
correctly with the reference implementations.

CVC5 passed all 21 configured packages/negative controls: eight packages ran
with the original driver, then the remaining thirteen with a temporary driver
using four Why3 workers. The proof obligations, solver versions, per-goal limits
and allowed exceptions were unchanged. As the existing ledger permits, CVC5
leaves `build_table`, `fill`, `place_apart` and `long_distance` unproved; Z3
proved them. All three negative-control packages were refused by both solvers.
The repository's normal proof driver and default worker count are unchanged.

The container's final ad hoc `git diff` check could not follow the copied jj
Git directory, so it was verified separately in the real checkout after
`moon info`: no generated `.mbti` changes. Earlier host gates/coverage were
replaced by the sequential exact-image run after their shared build directory
caused interference; those interrupted attempts are not counted as passing.

Native performance was measured in three alternating rounds on CPU 11, using
the same source and GCC with isolated old/new toolchains. zstd text means were
4.29/4.28/4.32 → 4.42/4.31/4.27 ms; Brotli text 3.37/3.34/3.37 →
3.43/3.32/3.49 ms; DEFLATE text 1.41/1.41/1.42 → 1.41/1.40/1.40 ms.
PNG plain was 2.32/2.35/2.31 → 2.37/3.40/2.31 ms; the middle new-toolchain
round was noisy (±238 µs), while its median is 2.37 ms versus 2.32 ms.
These measurements establish no speedup and do not justify an optimization
claim. Codec implementation and published performance tables are unchanged.

## Release preparation

1. Land shared policy/audit maintenance and each library's toolchain validation.
   These changes do not add a public MoonBit API; do not issue empty library
   releases just to move script/CI metadata.
2. Prepare the next runner release with the new compatibility baseline, source
   pins, generated components and ABI inventory together. Bun async remains
   explicitly unstable; do not describe all runtimes as fully compatible.
3. After the runner is actually published, move the site's dependency/lockfile
   to that version, repeat verification without the local override, then review
   the deployment. The local override makes this integration reviewable earlier.
4. Ship consumer dependency changes with their next app releases. Recheck the
   registry at that point, since today's resolution is not a future release guarantee.
5. RISC-V maintenance stays separate from the ongoing debugger changes; OpenSBI
   boot is unverified until its fixtures are restored and the skipped checks run.

No release versions or tags were created. Public actions require approval of
the concrete per-repository diff and its remaining caveats.
