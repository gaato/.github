# MoonBit upstream review — 2026-11-07

Tracked by [#2](https://github.com/gaato/.github/issues/2). This round started
late: the pinned 0.10.17 fell behind three releases, and the canaries were red
from 2026-11-03 until this review. The trigger in
[MoonBit maintenance](../moonbit-maintenance.md#きっかけ) was added during this
round so that a release opens an issue instead.

## Scope and result

All active original MoonBit repositories moved to 0.10.20. The shared docs
audit keeps one byte-identical copy (md5 `593392f8fa3de8844da43befb6830b92`),
and its `moonbitlang/async` imports are now pinned. Before, the unpinned script
imports resolved to async 0.22.7, which no longer builds on 0.10.17. CI and
canaries are green. Releases are prepared but not published; see
[Release preparation](#release-preparation).

## Required changes

| Upstream change | Effect on our code |
|---|---|
| `} derive(...)` is deprecated syntax [0027]; `moon fmt` rewrites it to a `#derive(...)` attribute | Formatted every repository. `.mbt.md` code blocks are not formatted and were fixed by hand. The mbt-sdk generator now emits the attribute. discord.mbt's `gen_extends.py` and `docs_shape_audit.py` read it, and mttp's `runtime_gates.mbtx` skips attribute lines. Without these fixes, those scripts would have silently stopped finding types. |
| `String::view(start_offset~, end_offset~)` deprecated [0020] | Replaced with `clamped_view` or `exact_view`, choosing whichever matches the original bounds behaviour at each site. |
| `cancellable_defer` [0098] | Wrapped in `@async.protect_from_cancel` where the code runs on moonbitlang/async (discord.mbt and discord_voice, docs-bot). The warning is suppressed with a stated reason in runtime-independent modules (`sdk-runtime`, mttp), because the core runtime's `protect_from_cancel` would be the wrong scheduler there. |
| `JsonPath` Show/Debug output changed | discord.mbt tests compare the path text instead. |
| moonbitlang/async 0.22.7 needs `moonbitlang/core/async` | Script imports are pinned. discord.mbt moved to 0.22.7, and mbt-sdk's http-async does so in PR #78. |
| A stale `_build` makes `moon fmt` a no-op ("no work to do") | Run `moon clean` before `moon fmt` after switching toolchains. |

## Adoption decisions

| Upstream change | Decision and concrete effect |
|---|---|
| `encoding/percent` | **Adopted in requesto.** Removes its private percent decoder; userinfo now uses `decode_lossy`. A 300,000-input differential check found identical behaviour. The RFC 8187 `ext_value` keeps its own encoder, because it preserves more characters than core. mbt-sdk already used core. |
| `argparse` `parse_outcome` | **Adopted in kbbi.** Help, version and failure are now values, and `rumah --help` is testable. The version string lives in one constant that gates compare with `moon.mod`. discord-cli is **deferred** until its CLI is next touched; the benefit there is only testability. |
| `@env.exit` + `eprintln` | **Adopted** in kbbi, discord-cli, mooncakes-graph and the mbt-sdk/codecs scripts. This drops `moonbitlang/x` from the three CLIs. On wasm, exit now goes through WASI `proc_exit`. For every exit path, moonrun 0.1.20261104 and moonrun-js produced identical stdout, stderr and exit codes, before and after the change. |
| async 0.22.7 (IPv6 literal hosts, malformed Set-Cookie ignored) | **Adopted in http-async** (PR #78). IPv6 literal origins and proxies work. One malformed `Set-Cookie` line no longer fails the whole response. The documented limitation is narrowed rather than removed, because async still resolves IP literals through `getaddrinfo` with `AI_ADDRCONFIG`. That fails on hosts whose only IPv6 address is loopback, Docker included. |
| core `compress/flate`, `gzip`, `zlib`, `archive/zip` | **Measured, consumers not migrated.** The codecs bench now has core rows. Core's compressed sizes equal moonbit-community/flate's, it decodes at about that library's speed, and gaato/deflate's one-shot decoder is faster on every target. Core is still `experimental`, and adopting it would split the shared codec traits that http-async and the Discord gateway use. Reconsider when core leaves experimental and beats gaato/deflate in the bench on both speed and safety. |
| core/async (deferred on 2026-10-24) | **Deferred again, now for a different reason.** It ships, but every package is `experimental: true`. async 0.22.6 says core/async will eventually replace moonbitlang/async. Migrating would break discord.mbt's public `@async.TaskGroup` API and its consumers. moonrun-js already registers all the imports it uses. Reconsider when the experimental mark is removed or moonbitlang/async announces deprecation. |
| Core checksum consolidation | **Rejected for now**: `core/internal/checksum` cannot be imported from outside core. Reconsider if core exposes a public checksum package. |
| `path`, `assert_raise_async`/`expect_error_async`, `raise?` map callbacks, `stable_sort_by`, `ArrayView::zip`, UInt64 min/max | **Not adopted.** No call site improves. The new test helpers would drop the specific failure messages our tests carry, so new async tests may use them, but existing ones are not converted. |
| StringBuilder capacity hint now counts UTF-16 units (breaking) | No call site passes a hint. |

## Dependency resolution

- `moonbitlang/async` 0.22.5 remains the floor except in discord.mbt (0.22.7)
  and in PR #78 (http-async and the other mbt-sdk async modules). The shared
  docs audit stays on 0.22.5 everywhere so that its copies stay identical.
- kbbi's fixture script now pins `moonbitlang/x@0.5.6`.
- discord.mbt's voice shim moved to aes-gcm 0.11 and chacha20poly1305 0.11
  together, since both crates are on aead 0.6. They are built without their
  `getrandom` default: the shim never generates keys, and the default pulled in
  r-efi 6.0.0, which ships no license file.

## Runner

moonrun-js now follows moonrun `940aa18` and async `5c8d124`.

| Upstream change | Decision and concrete effect |
|---|---|
| Policy split (`source`, `transfer`, `filesystem/{grant,host,os}`) | Ported, reusing the upstream files. `filesystem/os.rs` is a stub, since the hosts perform every effect. The 13 policy-diff cases that changed upstream pass. |
| Policy loading and inheritance (intersected with an inherited ceiling) | Adopted. |
| `FileGrant`, WASI paths authorized through HostFs | Adopted. Directory identity held by OS handle is **not** adopted (D50): the JS runtimes have no handle-relative open or unlink. |
| CLI moved to `cli_support.rs` | Adopted. `--daemon`, `--virtual-process` and the IPC options are parsed and refused with a clear error (D49), because they are V8 supervision features. |
| `make_openat_job` / `make_removeat_job` | Registered. A directory parent fails with ENOSYS (D48), because resolving relative to the cwd could reach the wrong file and bypass policy. No released async calls it with a valid parent yet. |
| Test init `_initialize`, source maps through moonutil, legacy fs errors | Adopted. |
| Event-loop startup stall | Fixed in moonrun-js. The scheduler yields with `setImmediate`, and Node's IP regexes are warmed before guest code runs. The stall was behind most `reuse_addr` failures; upstream fixed the rest in the test itself (async `0f6ef07`). |
| Deno reports ctime in whole seconds | `timestamp_test` indexes 0 and 2 are recorded as D39, flaky, each on its own. |
| core/async tests run in the core suite | They now run as their own step with `-j 2`, which keeps the timing tests away from about 185 other core test processes. The comparison stays exact. When the lock tests fail (D16), the native helpers' panics interleave mid-line. These are accepted only if every piece spells a line from a recorded 22-line vocabulary, and only for D16. 39 real samples were accepted; 400 one-byte mutations were all rejected. |

Validation: typecheck, lint and unit tests pass (544 passed, 1 skipped). The
full compatibility matrix passes on Node, Deno and Bun. CI on `d18a5569` passed
the suite comparisons in all 6 dispatched runs. Two runs failed only in the live
Discord skills case, while Discord's API was returning 503.
